# Oracle 스키마 작업 지침

- 이 폴더는 회원, 판매자, 상품, 주문, 주문 항목, 상품 후기의 Oracle 12c 이상 스키마를 관리한다.
- 원본은 `sql/01_create_tables.sql`이다. 변경 후 이 폴더에서 `node generate-schema.mjs`를 실행해 `schema.sql`, `schema.dbml`, `schema.mmd`, `diagram.md`를 함께 갱신한다.
- `schema.sql`과 `sql/01_create_tables.sql`은 같은 생성 DDL이다. 빈 스키마에서 둘 중 하나만 실행한다. 기존 테이블에 재실행하는 마이그레이션 스크립트가 아니다.
- `sql/drop_tables.sql`은 데이터를 포함해 테이블을 삭제한다. 사용자 요청 없이 실행하지 않는다.
- 문자열은 `VARCHAR2(n CHAR)`, 금액은 `NUMBER(12,2)`, 식별자는 `NUMBER(19)`를 사용한다. 숫자 PK의 자동 증가는 `GENERATED BY DEFAULT AS IDENTITY`를 유지한다.
- `review."date"`는 대소문자를 구분하는 인용 식별자다. SQL에서 항상 큰따옴표를 사용한다. 이름 변경은 관련 코드와 함께 검토한다.
- `order_item`의 복합 PK `(order_id, product_id)`와 가격 0 이상, 수량 양수 CHECK 제약을 유지한다.
- FK, NULL 허용 여부, 기본값, 주석을 변경하면 DBML과 다이어그램에도 반영되었는지 확인한다. 삭제 스크립트는 자식 테이블부터 삭제하도록 유지한다.
- 비밀번호에는 단방향 해시를 저장하며 예제에도 실제 인증 정보를 넣지 않는다.
- 파일은 UTF-8로 저장한다. `diagram.md`는 Mermaid 지원 뷰어로 열고, `schema.mmd`는 Mermaid 원본으로 사용한다.
- 검증 시 생성 파일의 테이블 6개, FK 6개, 복합 PK와 CHECK 3개를 확인한다. 실제 Oracle 실행 여부는 별도로 명시한다.
